This page verifies that the host can run one benchmark case. It stops after the first `BenchmarkReport`; agent implementation and larger benchmark runs are covered separately.

Use XS for installation verification even when the eventual target is Xlarge or Fat-tree. It exercises the same SDK, native client-agent, observability, fault, scoring, and cleanup path with a much smaller resource footprint.

## Requirements

<Callout title="Linux host required" type="warn">
NetOpsBench depends on Containerlab and Linux networking primitives such as network namespaces and veth pairs. Windows and macOS hosts are not supported for runtime execution.
</Callout>

- Python 3.12+
- Docker
- Go 1.25+, Git, and a C compiler for the pinned Containerlab build and race tests
- An API key for the selected LLM provider

Install Docker:

```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER   # re-login after this step
docker run --rm hello-world
```

NetOpsBench builds its pinned Containerlab backend after Python installation. The system `containerlab` command can remain installed for other labs; SDK-created runtimes use the repository-owned binary.

If Docker reports a socket permission error after adding the Docker group, log out and back in, or start a new shell with `newgrp docker`.

## Install

```bash
git clone https://github.com/NetX-lab/NetOpsBench.git
cd NetOpsBench
python -m venv .venv
source .venv/bin/activate
pip install -e ".[agent]"
```

Build the runtime tools once (and rebuild after the packaged patch changes):

```bash
python -m netopsbench.platform.runtime.build_tools --test
docker build -f containers/client/Dockerfile -t netopsbench-client:pingmesh-v2 .
```

The builder verifies the pinned upstream archive and patch checksums, applies the patch in an isolated directory, and installs `containerlab` and `mgmt-link` under the Python package's `platform/runtime/_bin/`. It neither replaces `/usr/bin/containerlab` nor recompiles or restarts Docker. Offline builds may use `--archive /path/to/pinned-source.tar.gz` and a populated Go module cache. Missing or incompatible tools fail before deployment instead of silently using a slower backend.

### Privileged runtime operations

The ordinary SDK process runs as your user. Management veth creation and destruction run the same virtual environment's `netopsbench.platform.runtime.management` module through `sudo -n`. An administrator should authorize only the checkout and runtime directory used for this installation. The following creates scoped rules for a standard checkout with `.venv` (sudo 1.9.10+ argument regex support):

```bash
python - <<'PYRULES' > /tmp/netopsbench-runtime.sudoers
import getpass, re, sys
from pathlib import Path
repo = Path.cwd().resolve()
base = re.escape(str(repo))
worker = base + r'/\.netopsbench/runtimes/[A-Za-z0-9_-]+/worker-[0-9]+'
topology = worker + r'/[A-Za-z0-9_-]+\.clab\.yaml'
module = r'-m netopsbench\.platform\.runtime\.management '
prefix = f'{getpass.getuser()} ALL=(root) NOPASSWD: '
python = str(repo / '.venv/bin/python')
for args in [
    module + 'deploy -t ' + topology + r' --reconfigure( --max-workers [0-9]+)?',
    module + 'destroy -t ' + topology + r' --cleanup( --max-workers [0-9]+)?',
    module + r'destroy --name [A-Za-z0-9_-]+ --cleanup( --max-workers [0-9]+)?',
]:
    print(prefix + python + ' ^' + args + '$')
for operation in ('stop', 'start'):
    print(prefix + str(repo / 'netopsbench/platform/runtime/_bin/containerlab') + ' ^' + operation + ' -t ' + topology
          + r' --node [A-Za-z0-9_-]+ --timeout 120s$')
paths = worker + r'/(configs|clab-[A-Za-z0-9_-]+)'
print(prefix + '/usr/bin/rm ^-rf ' + paths + '( ' + paths + ')*$')
print(prefix + '/usr/bin/rm ^-rf ' + base + r'/\.netopsbench/runtimes/[A-Za-z0-9_-]+$')
PYRULES
sudo visudo -cf /tmp/netopsbench-runtime.sudoers
sudo install -o root -g root -m 0440 /tmp/netopsbench-runtime.sudoers /etc/sudoers.d/netopsbench-runtime
```

The restart controller restores management IP, routes, DNS reachability, and the namespace handle. A Docker restart still removes Containerlab data links and in-container agents; recreate the runtime to restore the complete benchmark topology.

Use a trusted checkout: this privileged module and its imported Python code are executable with root privileges. Custom workspaces or Python interpreter paths need matching administrator-reviewed rules. These rules do not authorize arbitrary Python commands. Controller state and logs live under `/var/lib/netopsbench/management/<lab>`; the SDK teardown stops that lab's DNS/restart controller and removes its owned management network.

### Large-topology defaults

The k12 profile selects 16 container creation workers and Pingmesh destination batches of 32. The backend creates both data-link endpoints directly, uses single-queue management veths with final interface names, delays SONiC data-interface activation until initialization, and bounds SONiC service startup and container queries. Full SONiC completion and runtime health gates remain enabled.

Generate current assets with `netopsbench benchmark prepare --scales xlarge,fat-tree-k12,fat-tree-k18`. Healthy scenarios use the same baseline and diagnostic episode lifecycle as fault cases. Complete observation windows are 66 seconds for Xlarge and 42 seconds for K12/K18. Xlarge and K18 use two clients per rack with 50 PPS per client. K18 has 405 switches, 324 clients, and a `/22` management subnet. Pingmesh plans are generated once; client processes execute the fixed peer/port schedule. Coverage refers to topology candidate paths, not verified ECMP paths.

This refactor requires topology/runtime schema v4, scale profiles v2 and client configuration v2. Recreate old runtimes and regenerate their topology/scenario assets; old formats are rejected. Client addresses now start at `192.168.1.0/24`, and Fat-tree ASNs are allocated consecutively by tier. The default local image is `netopsbench-client:pingmesh-v2`; `NETOPSBENCH_CLIENT_IMAGE` selects another image built from the current source.

Run `PYTHONPATH=. python scripts/validate_pingmesh_scales.py` for sequential Xlarge/K18 acceptance. It measures XS resources, checks a 20% memory margin, runs native Codex XS smoke cases first, then evaluates DeepAgent (DeepSeek) and Codex sequentially on Xlarge/K18. It retains failed labs after fault recovery and tears down its own lab only after all requested cases and final health checks complete. Configure the DeepSeek API key and `codex login` before running; use `--agents deepagent` for DeepSeek alone. Coverage audits, capacity measurements and diagnosis reports are saved under `.netopsbench/validation-pingmesh-v2/`.

Capacity estimates are updated with the measured peaks from each completed scale. K18 requires a representative switch sample with at least 18 data ports and adequate available host memory. To continue K18 with an existing peak sample, run:

```bash
PYTHONPATH=. python scripts/validate_pingmesh_scales.py \
  --scales fat-tree-k18 \
  --capacity-sample .netopsbench/validation-pingmesh-v2/final/capacity-sample.json \
  --output .netopsbench/validation-pingmesh-v2/k18
```

For an explicitly monitored experiment, `--allow-tight-capacity` waives the
20% memory margin. The report retains the failed margin check and the override;
the measured peak estimate plus 8 GiB of available headroom, disk capacity, and
representative switch samples are still required.

To continue an interrupted acceptance on its existing runtime, use
`--resume-runtime /absolute/path/to/runtime --scales fat-tree-k18 --output /absolute/path/to/acceptance`.
The recorded vendor, runtime and plan must match. Valid completed cases are
retained, including low diagnosis scores; incomplete cases are rerun. The
attached runtime must pass health checks before execution resumes.
Provider/API failures are excluded from model acceptance, including fallback
`inconclusive` verdicts after an API error. Such cases must be rerun after the
provider is available; ordinary model conclusions and scores are retained.

Shared InfluxDB and Grafana containers are reused without automatic recreation during provisioning. Apply shared-service configuration upgrades explicitly when no active runtimes depend on them.

## Run one case

Supported provider presets:

| `--vendor` | Model | Environment variable |
|---|---|---|
| `openai` | gpt-5.5 | `OPENAI_API_KEY` |
| `minimax` | MiniMax-M3 | `MINIMAX_API_KEY` |
| `deepseek` | deepseek-v4-pro | `DEEPSEEK_API_KEY` |
| `zhipu` | glm-5.1 | `ZHIPU_API_KEY` |
| `kimi` | kimi-k2.6 | `KIMI_API_KEY` |

```bash
netopsbench benchmark prepare --scales xs
export OPENAI_API_KEY=...
PYTHONPATH=. python examples/01_run_scenario.py --vendor openai
```

The run provisions an XS topology, starts observability, injects one generated fault, calls the reference agent, scores the returned diagnosis, and writes a `BenchmarkReport`.

`netopsbench benchmark prepare` only generates topology and scenario assets. It does not deploy a lab, start telemetry, or reserve resources; deployment begins when a session or runtime command is executed.

## After success

- Open saved agent trajectories with `netopsbench trace view`; it syncs trace-enabled runs into the local Harbor viewer cache automatically.
- Implement your own agent with [Custom Troubleshooting Agents](/docs/build-your-agent/custom-agents).
- Run larger evaluations with [Running Benchmarks](/docs/run-benchmarks/run-scenario-vs-suite).
- Use [Operations](/docs/debug-operate/observability) only when a runtime, Grafana dashboard, or cleanup path needs inspection.

Acceptance resume requires the same selected scenario IDs and contents, profile, Pingmesh plan, client image and agent configuration. Valid zero-score diagnoses are completed cases; failed executions can be retried. Quarantined owned labs require `--rebuild-runtime`; external labs are never rebuilt or released by acceptance. SIGINT/SIGTERM request cancellation, recovery and an atomic checkpoint. Memory monitoring starts before deployment and protects the existing 12 GiB available-memory floor. Health checks share one elapsed-time deadline across all probes and retries.
